# 河洛卦：看清层次、时刻与范围

类型：传统术数与自我探索。知识版本：1（v0.6）。本文由项目自编，不复刻用户私有 Skill 的现代断语，不把计算结果包装成科学预测。

## 从应用取结果

读取 `context --profile UUID --date YYYY-MM-DD` 已可得到 `hexagrams`；单独查询用 `hexagrams show --profile UUID --date YYYY-MM-DD --at HH:mm`。需要完整出生时刻和明确填写的排盘性别。缺项时应用说明原因，不用姓名、生肖或默认中午猜填。

先看 `instant`、`timeZoneIdentifier` 和 `methodNotes`，再读具体卦。CLI 日期和参考时分按 Asia/Shanghai 解释，默认正午；河洛日界则使用出生档案的 IANA 时区零点，独立于八字的零点／23 点换日设置。查询绝对时刻相同，也不意味着不同时区档案的日卦边界相同。

## 五个层次

| 字段 | 含义与阅读方式 |
| --- | --- |
| `xianTian` | 按原局配数得到的先天卦，附元堂位置；不是对过去事件的证实 |
| `houTian` | 按元堂变爻及本算法内外卦规则得到的后天卦；不等同重新排八字 |
| `year` | 当前立春年对应的值年卦及当前爻，保留其起止时刻 |
| `month` | 十二节月中的值月卦；正月等标签指节月，不是农历月 |
| `day` | 当前节月内六日块及日序对应的值日卦；不是“每日一到凌晨按农历换卦” |

卦的 `lines` 按**自下而上**排列，`true` 为阳爻、`false` 为阴爻。卦名和文王序、上卦和下卦均直接采用应用字段。`linePosition`、`triggerLinePosition` 是算法标记，不应随意把元堂、触发爻和每日当前爻混成同一个概念。

## 日期边界与缺项

年卦和岁序以立春精确时刻推进；月卦在十二节的精确交接时刻切换。周期含开始、不含结束。交节发生在当地一天之中时，同一天可能有前后两个不同的月卦／日卦。解释时应说“在所选参考时刻”并给出有效区间，不能把正午取值当全天恒定结果。夏令时切换日按当地自然日推进，不按固定 86400 秒切块。

出生前或超出先后天各六爻岁序覆盖后，应用可以保留先后天卦，而年、月、日周期为空，并通过 `flowUnavailableReason` 说明原因。`nominalAge` 是算法中的立春岁序，不是周岁或法定年龄。周期结束只是当前算法范围，不能用来谈论寿命。

原生实现参考用户授权的 `bazi-pro` 数表和排卦规则，但修正了原脚本公历年与立春年混用、次年小寒顺序、交节日缺段及超范围回退等边界。三元寄宫仍公开保留该参考脚本的分段约定，没有声称所有流派相同。仓库完整说明见 [河洛规则、边界与验证](https://github.com/Gaomin-today/lingxing-calendar/blob/main/docs/heluo-v0.6.md)；实际结果以安装版本返回的 `methodNotes` 为准。

## 怎样解释给用户

先回答“所选时刻是哪一卦”，再说明它属于哪一层、何时生效、当前爻在哪里。`theme` 和 `reflection` 是本应用原创的简短观察提示，不是古籍原文或卦爻辞译文。深入引用经典或地方传统时，另行注明实际来源和口径。

用卦象提供一种审视现实问题的角度：例如遇到分歧时先澄清条件，想推进项目时检查可执行的下一步。对行程、签约或面试仍以真实信息和准备工作为主，不因某个卦名自动取消安排，不承诺结果。河洛卦不充当旺衰主证据，不自动推出喜用神，也不会决定用户该选哪一款灵宠或颜色。
