# v0.4 个人日历解读

`PersonalDailyReadingEngine` 把已经计算好的出生四柱、参考时刻四柱转成中文报告。它不联网、不调用模型、不重新排盘，也不保存出生资料。

```swift
let report = try PersonalDailyReadingEngine().analyze(
    natal: natalChart,
    flow: selectedTimeChart,
    strength: profile.strengthAssumption ?? .unspecified
)
```

`BaziStrengthAssumption` 是 `String / Codable / CaseIterable / Identifiable / Sendable`，包含 `unspecified / strong / weak`。由用户明确选择，仅用作解读假设；旧档案缺省为未确定。它不表示体能、心理能力，也不是程序计算出的旺衰结论。

## 报告的内容

- `headline / summary / actions`：流日十神的通俗主题、所选假设下的条件性解释与实际可做的事情。
- `periods`：流年、流月、流日分别以本层天干对出生日干计算十神，保留真实干支和层次，不把流年误写成流日。
- `natalMonth / flowMonth`：分别说明出生月令与当前流月的月支本气、五行生克、对应十神。流月天干十神与月支本气十神是两个字段。
- `observations`：已知其他天干中的同类、生扶，地支中的根气线索，以及仍需核对的命局条件。
- `rootEvidence`：逐项保留出生年、月、日、时柱位置、实际干支、藏干、是否本气。阴阳不同但五行相同也属于同五行线索。
- `relationships`：复用已有五合、六合、六冲、六害规则，逐条注明流日与出生哪一柱配对；不会用生肖取代完整柱位。
- `scopeNote`：集中说明尚未分析的条件与现代建议的性质，避免每条建议都重复长段警告。

各观察、月令与周期结果都带有 `sourceTitle / sourceURL / ruleNote`；周期的 `tenGod.explanation` 是本层的确定性生克解释，`conditionalInterpretation` 是传统假设下的反思，`action` 是现代行动转译。

## 规则与限制

十神复用 `BaziRelationshipEngine` 的日主生克和阴阳规则，输出自身、我生、我克、克我、生我五类的正偏名称。年、月、日只采用已传入的准确四柱，不根据公历年份、农历月份或设备时区重新猜测。出生盘与参考盘可以各自保留已明确的民用时区口径。

月令首先来自四柱引擎的十二节换月结果；本批只取通行藏干表的第一项作为本气观察。它不是交节后逐日的人元司令。辰戌丑未的杂气尤其不能用一个土元素把整月概括成同样的旺衰程度。本气与日主同五行只写为得令线索，生扶、泄出、耗用、约束也只写为关系。

同类与印星观察不把日干自身再次计入。藏干只观察成员与位置，不赋予 0.6、0.3、0.1 等数字权重，不把重复柱位合并，不据藏干数量给分。没有命中同五行藏干时写“已知地支暂未见”，不能声称已经确认无根或身弱。

选择身强时，普通扶抑思路引导到疏导、产出、目标和边界；选择身弱时引导到准备、支持、任务负荷与求助。正文都使用“若……假设成立”，不会将食伤、财官或印比直接认定为此人的喜用神，更不会给好运百分比、事件概率、升职发财、灾祸、疾病等承诺。假设变化不改变十神、月令、藏干或合冲事实。

未知时刻的 `hour == nil` 保持缺失，报告说明仅观察三柱。若出生日期本身存在多个年/月/日候选，调用层必须先明确候选或分别显示；不得随意拿第一个当作唯一命盘。当前报告消费一张明确的候选盘，不自行合并候选。

本批没有综合调候、格局、从化、根气受损和大运来判断旺衰喜用。另有大运展示时，也不能把两个各自独立的模块拼成已经完成综合命断的表述。流日建议是个人日历的反思入口，不能替代现实日程条件。

## 参考与取舍

已读取项目内 `bazi-pro`、`wannianli-pro` 两个 `SKILL.md`，以及相关 `analysis-workflow`、`evidence-priority`、周期/每日 playbook 和 `bazi_chart/rules.py`。采用“确定性历法先行、月令与根气先于辅助标签、解释应落到行动”的组织方式。

未照搬 `bazi_chart/engine.py::_yong_shen_reference`：它把天干、地支和藏干按固定数字累加，并以“月令旺相或单元素分数 ≥ 3”生成身旺参考，不能成为本产品的自动旺衰判断。另外该函数身旺分支 `CONTROLS[CONTROLS[day_element]]` 并非日主的官杀元素（如木→土→水），因此也不能用作通用的“克泄耗”表。相关 playbook 中“喜神日/忌神日”“可能发生”式输出未作为确定性产品规则。

## 验证

`PersonalDailyReadingTests` 覆盖三层十神归属、月干与月支本气区分、十二月支的本气及生克、排除日干重复计数、透干生扶、同五行异阴阳根气、其他藏干位置、未知时柱、强弱假设不污染事实、合冲的原柱归属，以及假设序列化和可点击来源。

根气与藏干数据复用已有命盘详情表，准确日期、节气边界与日界继续由 `FourPillarsEngine` 及其边界测试负责。
