# v0.3 四柱、出生档案与流日关系

## 这一批的闭环

选择日历日期 → 查看任意参考时刻的四柱 → 新建／选择本地出生档案 → 查看本命盘 → 比较该流日与自己的十神和逐柱合冲关系。

四柱来自确定性 Swift 计算，解释来自显式规则和来源，AI 不参与生成日期或命盘。出生档案不进入聊天历史或云端上下文。

## 排盘口径

- 支持公历 1901–2099；排盘使用当地民用钟表时间和所选 IANA 时区，历史夏令时采用系统 tzdb。
- 立春**交接时刻**换年，十二节的交接时刻换月；中气不换月。日历上的民用农历年仍按春节换年。
- 年月交节为绝对瞬间；跨时区不会改变同一瞬间的太阳交接，日柱和时柱则依据当地民用日期和时间。
- 默认零点换日，可切换子初 23 点换日。两种口径都将 23–01 点视为连续子时；23 点起的时干由次日干推起，分别对应 lunar 的 `sect=2`／`sect=1`。
- 未知出生时间：按实际民用日内的交节、23 点与时区变化切分，列出不同年月日候选；每一候选的时柱均为空。多候选不输出混合成一个结论的日运。
- 不存在的日期或夏令时跳过的时刻拒绝保存。重复时刻采用第一次出现的绝对时间，同时在编辑器和命盘中提示；当前不提供重复时刻第二次出现的选择。
- 出生地是备注，不由地名猜时区；不做真太阳时。只展示四柱，不计算大运，因此不要求性别。五行标注表示天干五行和地支本气五行，不是旺衰评分。

## 算法来源与精度

太阳视黄经与 ΔT 计算取自 [lunar-swift 1.1.8](https://github.com/6tail/lunar-swift/tree/a7ec0e9b29f84a5d98b09b9ffd31145f17470d56)，固定提交 `a7ec0e9b29f84a5d98b09b9ffd31145f17470d56`。仅收录太阳计算子集，原数值表和公式未改；完整 MIT 许可在 `Vendor/lunar-swift/LICENSE`，应用包携带 `ThirdPartyNotices.txt`。

日柱基准为香港天文台 [2010 年三月年历](https://www.hko.gov.hk/tc/gts/astron2010/files/03_2010c.pdf)的 3 月 15 日甲子日，按公历日期差取六十循环，避免把夏令时的一天当作固定 24 小时。

交节与天文台六个分钟级时刻交叉核对：2025 立春、2026 立春／夏至／白露／秋分／冬至，计算结果四舍五入到分钟均一致。这是抽样核验，不是 1901–2099 每个时刻的秒级精度承诺。界面只显示到分钟，出生或查询时刻接近交节前后两分钟时提示核对。

原始参考：[2025 年 2 月](https://www.hko.gov.hk/en/gts/astron2025/files/2025cal02.pdf)、[2026 年 2 月](https://www.hko.gov.hk/en/gts/astron2026/files/2026cal02.pdf)、[2026 年 9 月](https://www.hko.gov.hk/en/gts/astron2026/files/2026cal09.pdf)、[2026 二十四节气](https://www.hko.gov.hk/en/gts/astron2026/files/2026SolarTerms24.pdf)。

## 从 Mac mini 迁来的技能

用户提供 `bazi-wannianli-qimendunjia-skills-20260917-151458.zip`。归档 SHA-256：`00fd225e23e9c7de27b6e23588cf30b315d8385c43dc0b4e17834539721bdb6e`。

本次完整保留 `bazi-pro` 与 `wannianli-pro`，共 473 个文件、2,630,715 字节，位于项目 `LocalReferenceSkills/`；逐文件 SHA-256 在其 `manifest.json`。ZIP 附带的奇门技能本批未使用。原件没有被修改。

这两个技能作为本地参考和跨语言回归基准，不需要作为用户应用的 Python 运行时。目录已加入 `.gitignore`，不随 GitHub 或 `.app` 发布；归档没有为整套自定义脚本及参考资料声明统一的再分发许可。

已经发现并显式处理的区别：

| 项目 | 迁入脚本 | 本次 Swift 应用 |
| --- | --- | --- |
| 依赖 | 两套均固定 `lunar_python==1.4.8` | 固定 lunar-swift 太阳计算子集，无 Python 运行时 |
| 八字默认时间 | `bazi-pro` 默认 `true_solar` | 当地民用钟表时间，明确不校正真太阳时 |
| 默认日界 | 两套主引擎均采用 `sect=1`，23 点换日 | 默认零点，可选 23 点；对照测试明确匹配口径 |
| 万年历快捷脚本 | `calendar_query.py` 存在非 Exact 年月日接口 | 交节按瞬间；主要对照 `wannianli.engine` |
| 万年历时区 | 主引擎 timezone 参数仅作回显 | 实际根据 IANA 时区转换；海外案例另测 |
| 八字时柱键 | 实际字段是 `pillars.time` | 不使用文档中误写的 `pillars.hour`，也不从合冲倒推时柱 |

真太阳时、大运、流年流月深解与完整黄历字段可继续利用这份参考库逐项迁移；本批不自动启用整套推断。

审查还发现：八字脚本的 `standard` 仅减去手填夏令时小时数；`current.liu_nian` 用公历年中取值，立春前不适合作为实时流年；`yong_shen_reference` 是人为权重启发式且有候选元素与说明不一致的问题。故本批仅把明确口径的四柱输出作为交叉核验对象，不搬入这些评分或预测。原始文件保持不变以便追溯。

已实际运行两套技能主引擎，提取 8 组合成回归样例写入 `Tests/Fixtures/reference-four-pillars.json`。测试输入没有真实个人档案。常规 `scripts/test.sh` 在纯 Swift 环境核对这些样例，无需原始技能目录。需要重新运行原始脚本时，使用 **Python 3.10+**、项目内的技能目录与隔离依赖：

```sh
python3 -m pip install --no-deps --target build/python-reference/site-packages lunar_python==1.4.8
python3 scripts/verify-reference-skills.py
```

这里的 `python3` 必须是 3.10+；macOS 的系统 Python 3.9 会得到明确版本错误。验证脚本不写原始技能文件，依赖版本、引擎哈希或结果变化时会失败并要求检查。由于 Python 与 Swift 库同属 ShouXing 算法家族，对照只能证明本次口径兼容；独立精度参考仍是上面的天文台资料。

## 传统关系的范围

当前比较流日天干相对日主的十神，以及流日干支相对已知命盘各柱的五合、六合、六冲、六害。每条说明都保留柱位、配对名称和古籍来源。来源和规则表见 [bazi-relations.md](bazi-relations.md)。

“相合／相冲／相害／并见／平和”是本批规则命中的分类，不是综合吉凶等级。平和只是所选配对未命中。没有计算旺衰喜用、格局、藏干、合化、大运、三合、刑破，不能把此模块叫作完整个人运势预测；不提供健康、财务或人生结果断言。实际行动提示是现代自我反思建议。
