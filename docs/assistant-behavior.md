# 第一版助手的可验证行为

助手核心在本地工作，不依赖联网服务。中文日程解析使用确定性规则；日期、重复规则和时间计算使用 Gregorian Calendar 与 `Asia/Shanghai` 时区。解析器不调用语言模型、不直接保存日程，界面应先展示识别结果，由用户确认保存。

## 自然语言创建日程

支持这些输入：

- `提醒我明天下午三点开会`
- `后天上午十点半面试`
- `2026-09-20 15:30 签约`
- `9月20日下午两点签约`
- `下周一上午九点开会`
- `每天晚上八点读书`
- `每周三下午三点开会，持续一个小时，提前三十分钟提醒`

默认时长为 60 分钟，提前 10 分钟提醒；`不用提醒` 返回 `reminderMinutes = -1`，由通知层解释为关闭。重复规则为 `none`、`daily`、`weekly`。支持“持续半小时”“持续 90 分钟”等明确时长，最多 24 小时；提醒最多提前 7 天。

“每天”和“每周三”从下一次尚未过去的对应时间开始。“本周”“这周”及没有前缀的“周三”指本周；已过去时会要求重新确认，不自动移到下周。没有年份的月日采用当前年份，若已过去会追问，不自动跨年。公历输入校验范围为 1900—2100 年，闰日、月份长度与年界均由历法校验。

以下情况会追问，不生成待保存事件：

- 缺少日期、具体时间或日程名称。
- 裸“三点”这类上午/下午不明确的时间，或“晚上十二点”这类跨日歧义。
- 不存在的日期、越界的小时与分钟，已过去的一次性时间。
- 一条指令包含多个日期、多个开始时间或冲突的重复规则。
- 直接用农历创建日程，或涉及无法确认的外国时区。

算卦、宜忌、运势、询问是否适合某事等聊天，不触发创建。“修改”“取消”等命令也不会被误当成新日程；第一版引导用户在日历中编辑和删除。

## 建议与聊天

`AdviceContent` 明确分为 `fact`、`tradition`、`action` 三段。建议引擎只自行输出经过系统历法格式化的公历日期；农历、干支、节气、节日应由历法模块提供，不能使用助手生成的文本替代。

面试、出行、签约、会议分别提供具体准备清单。民俗段落只描述一般性的祈愿或个人仪式，明确不是当日宜忌，也不保证结果。没有经核验的黄历数据时，不编造“宜签约”“忌出行”等结论。节日和神诞问题引导用户查看日历里的来源与地域注释。

“算卦”“运势”在离线模式下引导反思、梳理不确定性与下一步行动，明确未进行卦象计算，不预测未来。心事情境提供轻量陪伴，不作诊断。日程聊天只引用调用方传入的当前日期日程名称，不自行假定访问了所有日历。

后续接入在线模型时，应保留确定性时间解析、工具调用校验、保存前确认，以及历法事实与传统说法分开的数据结构。
