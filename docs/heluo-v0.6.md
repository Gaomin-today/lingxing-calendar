# 河洛卦 v0.6：规则、边界与验证

河洛卦用于给个人日历提供传统文化和自我探索的辅助视角。计算是确定性的；卦象没有被当作事件发生概率、旺衰主证据或寿命判断。应用不随附用户私有知识库里的现代解读全文。

## 输入与输出

`HeluoEngine().calculate(for: profile, at: instant)` 返回可编码的 `HeluoReport`：

- 先天卦、后天卦及元堂位；六条爻以**自下而上**的 `Bool` 数组表示，`true` 为阳爻。
- 值年、值月、值日卦，以及明确的开始/结束时刻和当前爻；区间含开始、不含结束。
- 先后天各六爻的完整岁序表、当前段、天数地数、时区和口径说明。
- 不能计算周期时保留先后天卦，周期为空且附原因。缺出生时刻或排盘性别直接返回明确错误；不以中午、名字等猜补。

档案与查询民用日期均限 1901–2099 年。1900 和 2100 仅用于补齐交节边界，1901 年立春前归属 1900 立春年。先后天各六爻轮行结束后不继续扩张算法，也不照搬参考脚本的“返回最后一段”行为；这只是算法覆盖范围。

## 实际采用的规则

原生移植依据用户授权复用的 `bazi-pro/bazi_chart/heluogua.py` 及其数表。公开仓库只包含本次原生实现、合成数字样例、传统卦名，以及本应用原创的简短反思提示。

1. 四柱天干取配数，地支取河图奇偶数；奇数累计为天数，偶数累计为地数。天数以 25、地数以 30 归约；5 依三元寄宫。按年干阴阳与明确填写的排盘性别决定上下卦。
2. 子至巳为阳时，午至亥为阴时。按同类爻数量及参考脚本元堂诗例确定元堂。
3. 元堂变爻后交换内外卦得后天卦。坎、屯、蹇的第五/第六爻例外，依据出生农历月奇偶决定是否交换。闰月使用其月份绝对值。
4. 从元堂起依次走六爻，阳爻 9 年、阴爻 6 年，先天走完再走后天。后天仍使用参考脚本定义的同一元堂爻位。
5. 阳爻段流年先按起段年阴阳处理本爻，再变应爻、再变本爻，此后顺次递变；阴爻段从本爻起顺次递变。
6. 正月从年卦当前爻下一位变起。奇月在前一个奇月卦上顺变；偶月在对应奇月卦上变其应爻。
7. 当月卦当前爻下一位是首个六日块的触发爻；每六个当地自然日，触发爻上移一位。每块都从**当月原卦**变一次，不累计上一个日卦。块内每日从初爻到上爻递进。

三元寄宫**明确沿用参考脚本的分段**：1924 年前上元、1924–1983 中元、1984 年起下元。脚本未定义 2044 年后新循环，本版也没有悄悄补一套循环公式。使用 2044–2099 年出生资料时仍是“该脚本下元口径”，不是宣称所有河洛流派一致。

## 对参考脚本的边界修正

以下是应用公开采用的统一口径，不能声称与原脚本所有日期逐字等价：

| 原脚本行为 | 本版行为 |
| --- | --- |
| 年卦、岁数按公历年份递进，月卦却按立春起 | 年卦与岁序统一按立春年：出生所在立春年为 1，每过立春加 1；此值不是周岁，也不称为法定年龄 |
| 当前年节气表的“小寒”取同年 1 月，排在 12 月“大雪”之后，产生倒置月区间 | 寅月至子月取当年节，小寒明确取下一年 1 月，下一年立春封闭全年 |
| 立春前查询可能落不到月区间，默认取首月 | 找到真正包含查询瞬间的上一立春年及所属节月；找不到边界即报错 |
| 日表不包含结束交节当天；查询找不到就返回末日 | 交节日保留前后两个半开时间段：交节前属于旧月日卦，交节瞬间起属于新月首日卦。不存在回退到别的日期 |
| 超出先后天段后仍取最后段，继续向外变化 | 年/月/日为空，先后天保留，并说明范围；不外推、不作寿命判断 |

“正月、二月”等标签在这里是**十二节月**，不是阴历月份或公历月份。节气按绝对天文时刻归属。日卦的自然日边界固定为所选时区的零点，独立于档案八字的“23 点换日”设置。

因此交节当天可能有两个不同的月卦/日卦：例如当地 20:00 交节，20:00 前沿用旧月，20:00 起进入新月。界面必须显示取值时刻或区间，不能把一张整日卡伪装成整天不变。

## 时区与夏令时

参考脚本的常见标准时间使用固定 UTC+08:00。应用四柱使用档案中明确选择的 IANA 时区和历史夏令时，交节比较使用绝对时刻；日卦以查询时刻在**该档案时区**的民用日期递进，不用 86400 秒硬除。夏令时切换日可有 23 或 25 小时。

至尊卦例外中的出生农历月仍沿用参考算法的“所填出生民用年月日对应中国农历”的口径：用该民用日期传入 LunarSwift，不额外将整份档案改写为北京时间。未做经度或真太阳时校正。与固定 UTC+08:00 样例不同的时区可能产生不同四柱，这是输入口径差异。

## 解释文本

六十四卦名、文王序和阴阳爻是传统通用表。`theme`、`reflection` 是本应用原创的简短观察角度，例如“小步积累”“分歧与协商”；不冒充古典卦辞译文，不转载私有现代注解，不自动断言会发生具体吉凶。未来若由外部 Agent 深入解释，应让 Agent 读取明确授权的知识库，并以八字结构、真实日程和反馈为主。

## 验证与复现

`Tests/Fixtures/heluo-reference.json` 包含 173 个完全合成出生/查询组合和 64 卦数字表。生成器直接调用用户本地参考脚本的配数、元堂、后天、寿段、年卦和月卦公式；只归一化上表已声明的年/月/日边界。现代解读文本没有进入输出。记录参考源 SHA-256 以便辨识算法版本。

```sh
python3 scripts/generate_heluo_fixtures.py \
  --skill-path /path/to/private/bazi-pro \
  --dependency-path /path/to/isolated/lunar-python-1.4.8
```

原生自动检查覆盖：173 组合的四柱、天地数、先后天、元堂、年/月/日卦及当前爻；64 卦映射；缺失输入；立春精确交界；跨年小寒；六日块；23 点八字规则与零点日卦分离；23/25 小时夏令时日；先后天及最终岁序精确边界；出生前/超出岁序；1901/2099 边缘及 Codable 往返。测试只使用合成资料。
