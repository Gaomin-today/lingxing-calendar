# Apple 日历与提醒事项接入

第一批使用 macOS 14+ 的 EventKit，通过系统已有的账户读取和修改记录。应用不自行登录 iCloud、Google 或 Exchange；账户能否同步、何时完成同步由 macOS 和对应服务处理。

## 连接与数据范围

- 日历与提醒事项分别由用户点击连接按钮，请求完整访问权限。启动不会主动弹出权限请求。
- 完整访问是显示已有日程所需的系统权限；应用只读取用户勾选的日历和清单。空选择不会变成“读取全部”。
- 写入新记录时必须明确选择可写日历或清单，不自动回退到系统默认日历。
- 外部数据只保存为内存中的值快照，不复制到本地 `events.json`。本地日程继续独立保存。
- 监听 `EKEventStoreChanged`，由 AppStore 重新读取当前日期范围和已选清单。每次查询与写入都会重新检查权限，权限被撤销后停止读取。

## 支持的操作

| 类型 | 支持 |
| --- | --- |
| Apple 日历 | 按日期范围读取；新建；编辑名称、时间、全天状态、备注、位置和单个相对提醒；删除 |
| 新建重复日程 | 每天、每周 |
| 已有重复日程 | 显示 EventKit 展开的每次发生；只修改或删除当前这一次，保留原系列规则 |
| Apple 提醒事项 | 读取选定清单；新建、编辑、删除；标记完成和恢复未完成 |
| 截止时间 | 无截止日期、只有日期、日期和时间 |
| 只读来源 | 可查看，禁用修改 |

提醒事项与日程使用不同语义：无截止待办不会被放进时间轴；系统记录的提醒由 Apple 管理，应用不应为同一记录另发一份本地通知。

只有日期的提醒事项按民用日期显示，统一映射到本应用的北京时间日期，保存时仍是没有小时、分钟和时区的浮动日期；不会因为 Mac 的系统时区不同而变成前一天。含具体时间的提醒事项保留原时区对应的实际时刻。

## 写入保护

保存、删除、完成操作会重新获取系统记录，并检查来源是否仍可写、记录是否仍存在、`lastModifiedDate` 是否与打开时相同，以及可见字段是否变化。记录已改变时返回明确错误，要求刷新后重新打开；不把失效记录当成新记录插入。

已有重复事件通过“来源标识 + 原始 occurrenceDate”重新定位具体发生项。`event(withIdentifier:)` 可能得到系列主记录，所以重复项使用日期范围查询并匹配原始发生时间，最终只用 `.thisEvent` 保存或删除。稳定 UI 标识通过记录标识和原始发生时间的摘要生成；EventKit 在外部同步或移动后可能更换其标识，此时旧草稿会失效。

已有记录只写用户改变的受支持字段。URL、可用性、结构化位置、优先级、复杂提醒等未编辑属性保留原值。只有提醒提前量发生变化，才把原提醒替换成所选的一个相对提醒；复杂提醒无法在简化编辑器中完整配置，需在 Apple 应用中管理。新建无截止待办不创建时间提醒。

以下记录第一版仅查看：

- 含参与者的记录，避免编辑时意外发送邀请或取消通知。
- 已有重复提醒事项，包括完成操作，避免改变复杂重复的后续生成行为。
- 系统未提供修改版本的记录，无法可靠检测其他应用的并发修改。

已有 Apple 记录不支持移到其他日历或清单，请在 Apple 应用中完成此操作。

## 本地转入与默认位置（v0.2.1）

连接页可指定日程／待办各自的默认保存位置，编辑器可选择是否记住本次位置，聊天草稿同时标出并使用该默认位置。原位置不可用时阻止写入，不自动回退本地。显示来源与保存位置分开；主动保存到的 Apple 来源自动加入显示列表。

已有本地日程可以在编辑器选择 Apple 位置并确认转入；普通待办同样支持，重复本地待办暂不支持。先检查本地可写，再创建系统记录；核对新记录仍存在且未改变后移除本地副本。清理失败时尝试撤销本次创建，且只接受本进程登记且未改变的新建回执；新建重复日程以 `.futureEvents` 撤销整个新系列。

若补偿也失败，则保留本地及系统回执、提示整理未完成，本次运行重试只核对并整理本地，不重复创建。系统记录已删除或改变时停止整理以保留本地。该期间本应用禁止修改系统副本；已成功转入的旧本地编辑器也不能再次新建。协调器状态保存在内存，不承诺进程崩溃时两个数据库的原子性；发生此类中断应先检查两边记录。权限授予和真实账户迁移仍需用户连接后验收。

## 打包要求与验证

应用的 Info.plist 需要 `NSCalendarsFullAccessUsageDescription` 和 `NSRemindersFullAccessUsageDescription`。若后续启用 App Sandbox，还需要 Apple 要求的日历个人信息 entitlement。应从打包后的 `.app` 验证权限流程，不能把命令行测试的权限表现视为发布应用的结果。

纯代码构建不请求权限，不修改真实账户。需要在用户主动连接后的专用测试日历／清单验证：读取与取消勾选、日程增删改、重复项只修改本次、无截止待办、日期无时间、完成与恢复、外部修改冲突、只读来源、权限撤销及系统同步后的刷新。

日期转换已用独立断言验证 6 项不变量，覆盖洛杉矶时区输入的日期型待办、北京时间展示、浮动日期往返与有时间待办的时区往返；该检查未实例化 EventKit store。
