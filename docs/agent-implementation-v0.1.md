# AgentRuntime M0/M1 与 M2 配置和质量面板

本次实现把 PRD 的首个可验证闭环放在独立的 `LingxiAgent` Swift target 中，避免改变现有历法、解析器、`AppAutomationRouter` 和 `AutomationMutationJournal` 的行为。

已落地的边界：

- `AgentRuntime` 是 actor，按 Quick/Deep 预算运行有限 Loop，支持取消、模型调用超时、读取轮数、工具调用数和模型调用数上限。
- `ModelGateway`/`AgentDriver` 是可注入协议；生产模型、测试 fake 和未来受限 sidecar 都通过同一接口进入。
- `TypedToolRegistry` 只允许八个只读领域工具名，限制返回体大小，不提供 Shell、任意路径、数据库或 EventKit 入口。
- `SkillRegistry`、`PromptContextBuilder` 和 `AgentConfiguration` 生成任务开始时冻结的上下文快照。硬策略位于人格、习惯和用户偏好之前。
- `EvidenceLedger` 为工具来源记录 `sourceRef`、revision、时间、证据类型、置信度和冲突集合；模型没有匹配来源的 claim 会被标为不确定。
- `TraceStore` 只保留阶段、工具、来源、校验和失败摘要，并限制长度，不保存完整提示词或思维链。
- 深度模式最多进行一次补读/修复；模型或工具超时后返回已核验部分并标记降级，不伪报完整成功。
- 云端模型可返回受限 JSON envelope，运行时解析 `conclusion`、来源绑定的 `claims`、`critic` 和只读 `toolCalls`；返回普通文本时安全降级，不把文本猜成结构化事实。

当前模块通过注入的 `ReadOnlyToolProvider` 与应用解耦。`LingxiApp` 已提供
`AppAutomationToolProvider`，把允许的只读工具映射到现有 `AppAutomationRouter`；聊天 UI
的非日程问答已经通过这个 runtime 运行，并显示阶段、依据摘要和不确定性。云端聊天使用
按本轮需要裁剪的工具注册表，出生档案、命盘、日笺和本地知识文件不会因模型工具调用而外发。
当用户明确说“记下来”“保存到日笺”或“保存分析”时，聊天 UI 会生成本地写入提议；用户
确认后才调用 Router 的 MutationJournal 路径，写后核对 revision，并提供一次撤销。模型
回复本身不能授予写入权限，R2 档案修改、删除和外部系统写入仍留在后续阶段。
自然语言创建本地日程的既有确认卡也已复用同一条 journal 写入和撤销路径；冲突时仍转入
原有编辑器二次核对，不会静默覆盖已有安排。

测试覆盖深度读取与 revision 引用、无来源断言降级、工具白名单与响应大小限制、模型超时后的降级返回；最新测试数量与实际 UI 验收见 [验证记录](verification.md)。

## M2：配置编辑、历史与生效预览

应用内偏好设置现在提供四个本地 Markdown 文档的独立编辑器：`SOUL.md`、`AGENT.md`、`USER.md` 和 `SKILL.md`。文档由 `LingxiAgent.AgentConfigurationRepository` 负责有界 UTF-8 读取、原样保存、SHA-256 revision、乐观锁和原子写入；首次修改也会归档内置默认值。历史记录使用带文档标识、时间、正文和 revision 的 JSON，旧的 `*-<document>.md` 归档仍可读取。损坏、超限或版本冲突会保留原文件并显示错误，不静默回退覆盖。

在「偏好设置 → 阿灵配置 → 编辑阿灵配置」打开独立编辑窗口。四份文档各自保留未保存草稿；默认内容与历史版本先载入草稿，核对并保存后生效。右侧可查看全部历史正文，或切换“已保存／当前文件草稿”的生效预览。关闭、丢弃或覆盖未保存内容会提示；保存失败保留草稿，外部编辑冲突可通过重新读取解决。

`AgentConfigurationSnapshot` 统一构造配置与受限聊天 Skill；预览与云端网关共用 `AgentSystemPrompt`，展示固定规则、完整配置层与要求的读取工具，实时日期、日程和会话数据在请求时另行加入。草稿预览只在本机运行，不调用模型。有效配置最多每文件 8000 字符／32000 UTF-8 字节，提示组装为四个文档预留空间，超过余量的工具正文整项省略并提示，避免截断配置或发送不完整 JSON。

修改对下一次 AI 对话请求生效，进行中的 AgentRuntime 保持开始时的值快照。离线固定回复不使用这些配置；启用远程 AI 后配置正文会发送至用户设置的服务，设置页明确说明。读取失败不会静默覆盖原文件，并阻止未修复配置下的远程请求；界面提供配置文件夹入口，修复或移走无效文件后可重新读取，载入默认草稿不会覆盖损坏文件。Skill 正文不增加工具、不关闭校验，也不绕过本地写入确认。

配置历史保存前版本，不承诺多个文件或外部编辑器之间的跨进程事务。

## M2：依据与质量面板

聊天顶部、每条 Agent 回复及偏好设置提供「依据与质量」入口。`AgentQualityStore` 在内存中保留最近 30 次任务的结果与 trace 摘要，支持删除和清空，不新增完整提示词、工具载荷或密钥的持久化。失败和取消也保留请求编号、模型、时间与阶段摘要。清除依据记录不会删除聊天正文。

`AgentQualityReport` 从模型最终结构化声明与本轮实际工具返回计算引用绑定：只有事实／知识声明进入分母，必须有完整且精确匹配的来源、revision 和证据类型，且同一来源不存在版本冲突。读取来源的通用 ledger 条目不进入覆盖率。模型推断和用户输入分别列示；没有结构化事实声明时覆盖率为空，不能将普通文本标成 100%。本地校验也采用同一判断，模型自报通过不能覆盖本地失败。

面板展示逐条声明状态、完整来源与 revision、读取时间、缺失／冲突／过期问题，以及耗时、读取轮次和网关步骤。网关步骤包含本地种子读取步骤，不能解释为 HTTP 请求次数。引用匹配只证明所引版本确实被读取，不证明模型陈述的语义正确。

固定评测使用真实运行时及本地存储／写入凭据组件，输入和模型回复均为受控合成样例。运行不联网，不读取生产数据；临时写入只在独立临时目录完成并清理。取消保留已完成的用例结果，不显示全套通过。该评测检查编排与保护逻辑，不代表远程模型准确率或生产 Router 的完整端到端效果。

M2 剩余：R2 复合操作合并确认、模型路由及可选第二模型复核。
